| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | Функциональные (Functionality)     |              |
| F1  | На сайте банка неавторизованный пользователь может видеть список стандартных депозитов с актуальными ставками. | Базовая функция для привлечения новых клиентов. |
| F2  | На сайте пользователь может подать заявку на депозит, указав Ф.И.О. и номер телефона. | Начало воронки продаж для новых клиентов. |
| F3  | В интернет-банке авторизованный клиент видит общий список депозитов и персональные предложения по ставкам. | Повышение лояльности существующих клиентов. |
| F4  | В интернет-банке клиент может подать заявку на депозит, выбрав счет для списания и указав сумму. | Основная функция MVP для существующих клиентов. |
| F5  | Подачу заявки в интернет-банке необходимо подтверждать одноразовым СМС-кодом. | Требование безопасности для финансовых операций. |
| F6  | Заявки, поданные онлайн, обрабатываются сотрудником бэк-офиса в АБС (ручной режим для MVP). | Четкое ограничение скоупа MVP. Автоматизация будет на следующем этапе. |
| F7  | Клиент получает СМС-уведомления о подтверждении ставки и об открытии депозита. | Важный элемент клиентского опыта. |
| F8  | В АБС должна быть реализована функция управления ставками по депозитам для сотрудников бэк-офиса (кредиты и депозиты). | Централизация управления ставками, уход от Excel-файлов. |
| U   | Удобство использования (Usability) |              |
| U1  | Интерфейсы на сайте и в интернет-банке должны соответствовать принятой в банке системе дизайна (брендирование, цвета). | Обеспечение единого и узнаваемого пользовательского опыта. |
| U2  | Интерфейс должен быть интуитивно понятным и удобным для пользователя. | Общее требование бизнеса для повышения конверсии. |
| R   | Надёжность (Reliability)           |              |
| R1  | Все новые сервисы должны работать в режиме 24/7. | Стандартное требование для онлайн-банкинга. |
| R2  | Доступность сервисов должна составлять 99,9%. | Архитектурно значимое. Влияет на выбор инфраструктуры и архитектуры. |
| R3  | Интернет-банк должен быть отказоустойчив к сбою одного из центров обработки данных (ЦОД). | Архитектурно значимое. Требует реализации резервирования и переключения между ЦОД. |
| P   | Производительность (Performance)   |              |
| P1  | Время отклика пользовательских операций в интерфейсе не должно превышать 1 секунду. | Критично для удержания пользователей. |
| P2  | Новое решение должно поддерживать горизонтальное масштабирование для равномерного распределения нагрузки. | Архитектурно значимое. Определяет подход к построению инфраструктуры и самих приложений. |
| S   | Поддерживаемость (Supportability)  |              |
| S1  | Для всех новых компонентов должна быть разработана техническая документация. | Упрощает дальнейшее развитие и поддержку системы. |
| S2  | Необходимо обеспечить логирование и мониторинг состояния новых сервисов. | Добавлено требование. Критически важно для оперативного обнаружения и решения проблем в продуктивной среде. |
| +R  | + Ограничения (Restrictions)       |              |
| +R1 | Для передачи чувствительных данных между клиентом и сервером необходимо использовать шифрование трафика (HTTPS). | Архитектурно значимое. Базовое требование безопасности. |
| +R2 | Следует максимально использовать существующие в банке технологии (MS SQL, Oracle, Java). | Снижает затраты на внедрение и поддержку. |
| +R3 | Новая функциональность по отправке СМС в интернет-банке должна быть реализована силами команды банка, без доработок ядра от подрядчика. | Архитектурно значимое. Требует создания собственного сервиса или компонента. |
| +R4 | Следует избегать прямых синхронных вызовов из интернет-банка в АБС из-за высокой нагрузки на базу данных АБС. | Архитектурно значимое. Ключевое требование, подталкивающее к асинхронной архитектуре (очереди сообщений). |
| +R5 | Система АБС может масштабироваться только вертикально. | Архитектурно значимое.Усиливает требование +R4, необходимо изолировать новые масштабируемые компоненты от АБС. |
| +R6 | Для асинхронного взаимодействия следует использовать Apache Kafka. | Архитектурно значимое. Прямое указание на выбор технологии, которое определит архитектуру интеграции. |
| +R7 | Новую функциональность в интернет-банке следует реализовывать в рамках микросервисной архитектуры. | Архитектурно значимое. Стратегическое решение об уходе от монолита, влияющее на все аспекты разработки и эксплуатации. |
